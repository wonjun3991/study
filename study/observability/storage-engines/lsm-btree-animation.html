B+tree: 제자리 갱신

한 페이지에 키가 최대 3개 들어가는 B+tree입니다. 삽입하면 루트에서 리프까지 페이지를 읽고, 리프 페이지를 원래 위치에 다시 씁니다. 페이지가 넘치면 둘로 나누고 가운데 키를 부모에 올립니다. 리프 사이 점선은 범위 스캔용 연결입니다.

      시뮬레이터에서 볼 것

      • B+tree는 키 하나를 넣을 때마다 쓰기 카운터가 1 이상 오릅니다. 분할이 일어나면 페이지 3개를 한꺼번에 다시 씁니다.
      • LSM은 PUT 4번까지 디스크 파일이 그대로입니다. 대신 compaction 때 같은 키를 여러 번 다시 쓰고, 이것이 쓰기 증폭 숫자로 나타납니다.
      • 같은 키를 다시 PUT하면 LSM에는 두 버전이 공존하다가 compaction에서 옛 버전이 사라집니다.
      • GET은 B+tree에서 항상 높이만큼 읽고, LSM에서는 bloom filter가 대부분의 파일을 걸러 줍니다.

      시뮬레이터가 단순화한 부분

      • B+tree 페이지 쓰기 수는 분할 시 고친 페이지 수를 더한 근사값입니다. 실제 DB는 redo log와 buffer pool 때문에 쓰는 시점이 미뤄집니다.
      • LSM은 memtable 4키, L0 3파일, 파일당 6키로 아주 작게 잡았습니다. RocksDB 기본값은 L0 4파일에서 compaction을 시작합니다.
      • MergeTree의 실제 merge 대상은 크기 기반 휴리스틱으로 고릅니다. 여기서는 같은 level의 인접 part 3개를 고릅니다.
      • bloom filter의 false positive는 약 10%로 흉내 냈습니다.
