## 🚨 무엇이 틀렸나

### 문제 1: 모델이 Qwen3.6이 아니었음

OpenCode Sisyphus agent의 default routing이 Claude를 가리킴. "Qwen3.6을 쓴다"는 **프롬프트 텍스트**일 뿐, 실제 provider 라우팅과 무관.

DB 검증 결과:
- Orchestrator: `claude-opus-4-7`
- T1-T4 subagents: `claude-haiku-4-5`
- T5 librarian: `claude-sonnet-4-6`

### 문제 2: 토큰은 추정치

v1 리포트의 "Sisyphus ~40K tokens" 주장 vs DB 실측 **5,417,765 tokens** (약 **135× 차이**).

원인: tool-call 횟수 기반 추정 → cache read (실측의 89.9% 차지)를 완전히 무시.

### 문제 3: Vanilla는 아예 실행 안 됨

"Goal rate 56%"는 behavioral model 기반 Bernoulli(p=0.70) 시뮬레이션. 실제 Vanilla 실행 결과가 아님.

## 교훈

1. **Provider 라우팅은 기본값에 의존하지 말 것** — agent별 `modelID` 명시 지정
2. **토큰은 추정하지 말고 provider API usage 필드를 직접 읽을 것**
3. **양쪽 configuration을 실제로 실행할 것** — 한 쪽만 돌리고 다른 쪽을 모델링하지 말 것
4. **결과의 "모델" 필드를 매번 검증할 것** — HTTP 응답의 `model`이 요청과 일치하는지
