# v2 쉬운 태스크 (Qwen3.6-plus 실측)

> **교훈**: 강한 모델은 쉬운 태스크를 혼자 푼다. Orchestration은 **효율성**에만 기여.

## 실행 내용

- **모델**: qwen3.6-plus (DashScope Anthropic-compat) — v1 오류 교정
- **하네스**: 자체 구현 tool loop (curl + Python)
- **태스크**: v1과 동일한 T1-T5 (탐색형)
- **Sisyphus 에뮬레이션**: T1 순차 → T2-T5 4-way ThreadPool 병렬 + task별 skill snippet 주입

## 실측 결과

| 지표 | Sisyphus × Qwen3.6 | Vanilla × Qwen3.6 | 비율 |
|---|---:|---:|---:|
| Wall-clock | 204.9 s | 349.1 s | 0.59× |
| Parallel segment (T2-T5) | 128.5 s | — | 2.14× speedup |
| Total tokens | 722,638 | 1,451,927 | 0.50× |
| Input tokens | 708,159 | 1,438,483 | 0.49× |
| Output tokens | 14,479 | 13,444 | 1.08× (동일) |
| **Goal satisfaction** | **5/5** | **5/5** | **동률** |

## 발견된 문제

**Qwen3.6-plus가 탐색형 태스크를 너무 잘 풀었음.** 양쪽 모두 5/5 goal 달성. Orchestration의 **품질 이점 측정 불가** — 이것이 v3로 넘어간 계기.

## Per-task

| Task | Sisyphus wall | Vanilla wall | Sisyphus tokens | Vanilla tokens |
|---|---:|---:|---:|---:|
| T1 | 76.4s | 63.7s | 136K | 69K |
| T2 | 60.7s | 84.0s | 53K | 224K |
| T3 | 128.5s | 118.1s | 440K | 718K |
| T4 | 32.5s | 46.0s | 17K | 224K |
| T5 | 53.1s | 37.2s | 74K | 214K |

**주목**: Vanilla는 T1 누적 context가 T2-T5로 전달되어 input tokens가 선형 증가. Sisyphus는 격리된 context로 소량 유지.

## 교훈

1. **Qwen3.6-plus는 탐색형 태스크에 충분히 강함** — orchestration 없어도 완벽
2. **토큰 절감은 isolated context에서 나옴** — 누적 재전송이 없어서 input 절반
3. **Wall-clock 단축은 parallel fan-out에서 나옴** — 2.14× speedup 재현
4. **품질 차이를 측정하려면 더 어려운 태스크가 필요함** (v3로 넘어감)
